# PayGuard 端到端演示脚本

建议时长 3–5 分钟（Mock 路线）或 6–8 分钟（真实路线）。开始前点击「重置演示」，保证状态为 `0 / 6`。

## 0. 场景开场

这是一个合成的 P0 事故：星海出行支付接口超时率突增，预估影响 ¥286.4 万。页面最上方是事故语境和累计执行指标；左侧是六步处置链路；中间展示本步骤实际输入、工具与输出；右侧解释产品门槛、成功指标、风险和降级策略。

核心交互原则是：一次点击只推进一个业务步骤。这样每个判断都能单独讲清楚，未来步骤的结果也不会提前泄漏。

## 1. 智能核验

点击「开始演示：执行智能核验」。

讲解重点：

- Metrics 和 Alert Context 两类工具共同核验异常，避免只靠单一指标下结论。
- 输出给出 `isIncident`、严重度、置信度和影响面，不输出隐藏的模型思维过程。
- 右侧门槛要求真实故障置信度达到 90%；不足时转人工校验，不能自动升级。
- 顶部累计耗时、Token、成本、工具调用和证据数同步增长。

## 2. 定位分析

点击「下一步：进入定位分析」。

讲解重点：

- Logs、Change Records 和 Case RAG 形成三类互补证据。
- Top-1 根因是“商户 API 网关连接池耗尽”，同时保留备选根因和证据引用。
- 产品目标不是生成一段看似合理的文字，而是把 AI 能力拆成可验证、可复现的结构化结果。

## 3. 商户触达与人工审批

点击「下一步：生成商户触达方案」。此时流程暂停，不会直接进入故障升级。

讲解重点：

- Merchant Profile 决定渠道和内容深度，Message Composer 只使用已确认事实生成通知。
- 触达是外部高风险动作，因此设置显式人工审批门槛。
- 可以展示摘要和 JSON 两种输出；点击「批准并发送」后，商户触达才记为完成。
- 如果点击「转人工处理」，Run 会进入 `needs_human`，保留此前 Trace；重置可重新演示黄金路径。

## 4. 故障升级

点击「下一步：执行故障升级」。

讲解重点：

- 系统根据 P0 等级和影响金额匹配升级策略，生成 Mock 工单并通知保障与网关团队。
- 输出明确标记 `simulated: true`，防止演示环境误触真实外部系统。
- 真正接入时由 `HttpIncidentRuntime` 调用工单、On-call 和消息服务，UI 无需改写。

## 5. 恢复判断

点击「下一步：判断是否恢复」。

讲解重点：

- 不是看到单点回弹就结束，而是校验连续三个时间窗口。
- 输出同时给出恢复状态、稳定窗口数、残余风险和观察建议。
- 降级策略是在窗口不稳定时继续观察或转人工，而不是强行闭环。

## 6. 评测回流

点击「最后一步：回流评测样本」。

讲解重点：

- 最终工单、人工审批和恢复结果组成事实标签。
- 系统生成 `EVAL-20260826-031`，记录核验 TP、Top-1 根因命中和人工修正情况。
- 评测不是一次性报告，而是随每次处置常态化回流。

随后点击左侧「AI 评测」，展示“本次演示样本”、模型/Prompt 实验、混淆矩阵和 Bad Case 队列。再进入「流程分析」，用漏斗说明全链路转化，用桑基图查看告警来源、根因、动作和恢复去向，用延迟与工具图定位优化机会。

## 可验证行为

- 每次主操作只新增一个阶段结果。
- 未来步骤的结构化输出不可见。
- 商户触达未审批时不能执行故障升级。
- 已完成阶段可点击回看，累计指标不会回退。
- 刷新页面后 Mock 进度恢复；点击重置后返回第 1 步。
- 所有事故、商户、金额、工具返回和评测结果均为合成数据。

## 真实 LLM 演示路线（可选，需本地配置）

前置：在 `.env.local` 配置 `key` / `url` / `model`（HTTPS、Anthropic Messages 兼容），详见 README。未配置时「真实 LLM」按钮禁用并提示检查配置，Mock 路线不受影响。

### 切换与核验图片

1. 点击顶部的「真实 LLM」。系统会新建一条真实 Run（不复用 Mock 进度），横幅显示 `REAL LLM MODE`、`MULTIMODAL` 和当前模型名。
2. 核验阶段显示内置合成监控截图（支付成功率、P95 延迟、Top 错误码）。可点击「替换核验图片」上传本地 PNG / JPEG / WebP（≤ 4 MB），也可「恢复内置截图」。
3. 点击「开始演示：执行智能核验」。这是全场唯一的多模态调用：模型同时读取截图和结构化指标，输出里的 `visualFindings` 能直接引用截图中的趋势（成功率跌破 71%、P95 升至 4800、504 主导）。

讲解重点：

- 阶段工作区会标记 `REAL LLM` 徽标、模型名和核验图片来源（内置截图 / 上传图片）；Mock 阶段标记 `MOCK`，两类输出不混淆。
- 真实调用耗时不确定，超过 2 秒会提示「模型正在分析图片与证据」，不伪造进度百分比。
- Token 与耗时为真实计量；成本在真实模式下不做估算，显示为「成本未估算」。

### 后续五阶段与审批

- 定位分析、故障升级、恢复判断、评测回流与 Mock 路线一致地逐阶段点击，但每一步都由真实模型基于前序结构化输出推理生成。
- 商户触达同样必须人工批准：点击「批准并发送」前流程不会进入故障升级。可以展示触达文案是模型基于已确认事实生成的，不是模板拼接。
- 完成后进入「AI 评测」，同样会看到本次真实 Run 回流的评测样本。

### 失败与降级

- 真实调用失败（鉴权、限流、超时、上游不可用、输出不可解析）时不会用 Mock 结果替代：当前步骤保留，可原地重试。
- 页面同时提供「切回 Mock 演示」一键回退，两条路径互不污染。
- 解析方差（如模型多写几条决策依据）由服务端自动截断收敛或重试一次真实调用，对讲解透明。
