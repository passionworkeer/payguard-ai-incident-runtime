# PayGuard 端到端演示脚本

建议时长 5–7 分钟（Mock 路线）或 8–12 分钟（真实路线）。开始前点击「重置演示」，保证状态为 `0 / 6`（黄金场景）或按当前演示场景的 `plannedStageCount`。

## 0. 场景开场

页面顶部是事故语境、累计指标和「演示场景」选择器。系统已内置 4 个演示场景，可随时切换（切换会丢弃当前进度，弹窗确认）：

- **网关超时（黄金路径）**：星海出行 P0 / ¥286.4 万 / 网关连接池耗尽，6 步线性闭环。
- **误报收敛**：麦田会员店 P2 / 疑似 ¥12.7 万 / 大促流量 4.1× 但成功率 99.48% 健康，2 步短路直达 evaluate，回流 TN 样本。
- **商户证书**：云杉生活 P1 / ¥64.8 万 / 签名失败 61.2× 证书过期，根因归属商户、触达含指导步骤。
- **渠道回回弹**：万象零售 P0 / ¥152.7 万 / 工行渠道 12.4%，recover 第 1 次判未稳定 + retryStages 换新窗口 → 第 2 次 recovered=true。

核心交互原则是：一次点击只推进一个业务步骤。所有分支（误报短路 / 恢复重入 / 转人工）由阶段 output 驱动：Mock 走 fixture，真实模式由模型自己判断 —— 不一致本身就是评测必要性的论据。

## 1. 智能核验

点击「开始演示：执行智能核验」。

讲解重点：

- Metrics 和 Alert Context 两类工具共同核验异常，避免只靠单一指标下结论。
- 输出给出 `isIncident`、严重度、置信度和影响面，不输出隐藏的模型思维过程。
- 右侧门槛要求真实故障置信度达到 90%；不足时转人工校验，不能自动升级。
- 顶部累计耗时、Token、成本、工具调用和证据数同步增长。
- 误报场景下 `isIncident=false` + `falseAlarmReason` 触发状态机短路 → 中间 4 步显示「已跳过」，2 步闭环。

## 2. 定位分析

点击「下一步：进入定位分析」。

讲解重点：

- Logs、Change Records 和 Case RAG 形成三类互补证据。
- Top-1 根因是「商户 API 网关连接池耗尽」，同时保留备选根因和证据引用。
- 新字段 `causeOwner` 区分「商户侧 / 渠道侧 / 平台侧」：商户证书场景归属商户侧，渠道回弹归属渠道侧，黄金路径无显式归属（隐含平台侧）。归属决定后续触达与升级策略。
- 产品目标不是生成一段看似合理的文字，而是把 AI 能力拆成可验证、可复现的结构化结果。

## 3. 商户触达与人工审批

点击「下一步：生成商户触达方案」。此时流程暂停，不会直接进入故障升级。

讲解重点：

- Merchant Profile 决定渠道和内容深度，Message Composer 只使用已确认事实生成通知。
- 触达是外部高风险动作，因此设置显式人工审批门槛。
- 商户证书场景额外渲染 `guidanceSteps` 三步指导（有序列表），并通过 `actionLinkLabel` 暴露商户行动入口。
- 渠道回弹场景触达文案为「安抚型」（`tone: 'reassurance'`），建议商户切回其他渠道。
- 可以展示摘要和 JSON 两种输出；点击「批准并发送」后，商户触达才记为完成。
- 如果点击「转人工处理」，Run 会进入 `needs_human`，保留此前 Trace；重置可重新演示黄金路径。

## 4. 故障升级

点击「下一步：执行故障升级」。

讲解重点：

- 系统根据 P0 等级和影响金额匹配升级策略，生成 Mock 工单并通知保障与网关团队。
- 商户证书场景下升级为「低级别通报」，仅通知商户技术支持（`escalationLevel`）。
- 渠道回弹场景升级对象为渠道运营与支付路由。
- 输出明确标记 `simulated: true`，防止演示环境误触真实外部系统。
- 真正接入时由 `LlmIncidentRuntime` 调用工单、On-call 和消息服务，UI 无需改写。

## 5. 恢复判断

点击「下一步：判断是否恢复」。

讲解重点：

- 不是看到单点回弹就结束，而是校验连续三个时间窗口。
- 输出同时给出恢复状态、稳定窗口数、残余风险和观察建议。
- 渠道回弹场景：第 1 次判 `recovered=false, stableWindows=1`（窗口 2 回弹至 81.4%），状态机停留 recover；点击按钮文案变为「再次判断是否恢复（上一轮回弹）」，第 2 次 fixture 换新观测窗口 → `recovered=true`；totals 显示「恢复重试 1 次」。
- 降级策略是在窗口不稳定时继续观察或转人工，而不是强行闭环；连续 3 次 recovered=false 触顶转人工，展示 `humanReason` 原因说明。

## 6. 评测回流

点击「最后一步：回流评测样本」。

讲解重点：

- 最终工单、人工审批和恢复结果组成事实标签。
- 系统生成 `EVAL-20260826-xxx`，记录核验 TP / Top-1 根因命中 / 人工修正情况。
- 评测不是一次性报告，而是随每次处置常态化回流。

随后点击左侧「AI 评测」：

- **顶部「本次会话实时评测」**：最近 20 条样本、实时 Accuracy / Precision / Recall / F1 / 根因命中率、混淆矩阵。每次 Run 完成时自动 append，刷新页面仍在。
- **下方「历史演示数据（静态基线）」**：与本次会话评测隔离，避免误读。
- 跑 4 场景一遍可直观看到：黄金路径 / 商户证书 / 渠道回弹三条 TP，误报一条 TN；前 3 条根因命中 Top-1，最后一条 n/a。

再进入「运营总览」：

- **三层指标**（北极星 / 一级 / 护栏）：MTTR 18.6m（与下方分解加和自洽）、P0 召回率 98.7%、自动处置率 78.4%、误报率 4.2%。
- **MTTR 分解**堆叠条：发现 2.4 / 核验 1.8 / 定位 4.6 / 触达 3.2 / 恢复确认 6.6，合计 18.6m。
- **告警量 vs 事故量**双轴 + 事故窗口阴影（验证 markArea 注册生效）。
- **成功率 / P95 双轴**+ 基线 99.5% markLine。
- **原始告警流**：4 场景商户 + 噪声告警，verdict 区分误报 / 确认 / 处理中。

## 可验证行为

- 每次主操作只新增一个阶段结果；误报场景 2 步即闭环，恢复重入第 2 次按钮文案明确。
- 未来步骤的结构化输出不可见。
- 商户触达未审批时不能执行故障升级。
- 已完成阶段可点击回看，累计指标不会回退。
- 刷新页面后 Mock 进度恢复；点击重置后返回第 1 步。
- 所有事故、商户、金额、工具返回和评测结果均为合成数据。

## 真实 LLM 演示路线（可选，需本地配置）

前置：在 `.env.local` 配置 `key` / `url` / `model`（HTTPS、Anthropic Messages 兼容），详见 README。未配置时「真实 LLM」按钮禁用并提示检查配置，Mock 路线不受影响。

### 切换与核验图片

1. 点击顶部的「真实 LLM」。系统会新建一条真实 Run（不复用 Mock 进度），横幅显示 `REAL LLM MODE`、`MULTIMODAL` 和当前模型名。
2. 核验阶段显示内置合成监控截图（支付成功率、P95 延迟、Top 错误码）。可点击「替换核验图片」上传本地 PNG / JPEG / WebP（≤ 4 MB），也可「恢复内置截图」。
3. 点击「开始演示：执行智能核验」。这是全场唯一的多模态调用：模型同时读取截图和结构化指标，输出里的 `visualFindings` 能直接引用截图中的趋势（成功率跌破 71%、P95 升至 4800、504 主导）。

讲解重点：

- 阶段工作区会标记 `REAL LLM` 徽标、模型名和核验图片来源（内置截图 / 上传图片）；Mock 阶段标记 `MOCK`，两类输出不混淆。
- 真实调用耗时不确定，超过 6 秒会提示「模型正在分析图片与证据」，不伪造进度百分比。
- Token 与耗时为真实计量；成本在真实模式下不做估算，显示为「成本未估算」。
- **分支由模型真实判断**：误报场景下模型完全可能判 `isIncident=true`（这是真实模型的局限，不视为 bug）—— 切回 Mock 路线即可演示标准短路闭环。

### 后续五阶段与审批

- 定位分析、故障升级、恢复判断、评测回流与 Mock 路线一致地逐阶段点击，但每一步都由真实模型基于前序结构化输出推理生成。
- 商户触达同样必须人工批准：点击「批准并发送」前流程不会进入故障升级。可以展示触达文案是模型基于已确认事实生成的，不是模板拼接。
- 渠道回弹场景下真实模型可能在第 1 次 recover 判 recovered=false，第 2 次 fixture 提供新窗口后判 recovered=true —— 与 Mock 行为对齐。
- 完成后进入「AI 评测」，同样会看到本次真实 Run 回流的评测样本（混淆矩阵中会有真实 / 误报各自的真实判分）。

### 失败与降级

- 真实调用失败（鉴权、限流、超时、上游不可用、输出不可解析）时不会用 Mock 结果替代：当前步骤保留，可原地重试。
- 页面同时提供「切回 Mock 演示」一键回退，两条路径互不污染。
- 解析方差（如模型多写几条决策依据）由服务端自动截断收敛或重试一次真实调用，对讲解透明。
