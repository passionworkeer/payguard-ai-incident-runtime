# PayGuard 商户故障 AI 处置台

PayGuard 是面向「支付宝事业群 - AI 产品解决方案工程师」岗位制作的交互式作品集 Demo。它用一条可观测、可评测、有人机协同节点的 AI 流程，展示从商户故障核验到恢复判断的完整处置闭环。

> 本项目中的事故、商户、指标与模型结果均为合成数据，仅用于产品方案与交互演示，不代表支付宝或蚂蚁集团的真实业务数据。

## 亮点

- 五阶段 AI 处置链路：故障核验、定位分析、商户触达、故障升级、恢复判断。
- 阶段级可观测性：延迟、工具调用、Token、成本、置信度、成功率与人工接管率。
- 流程分析：桑基图、漏斗图、P50/P95/SLA 延迟、工具使用与触达转化。
- 评测工作台：准确率、召回率、F1、严重度召回、混淆矩阵、实验对比与 Bad Case。
- 证据链抽屉：结构化判断、证据引用、各阶段 Trace 与商户触达文案预览。

## 本地运行

```

```

## 3 分钟演示路线

1. 在「运营总览」说明 6 个核心指标如何覆盖业务结果、AI 效果与成本三类目标。
2. 点击「启动一次 AI 处置」，观察五个阶段的耗时、工具调用与置信度；流程会在商户触达前暂停，体现高风险动作的人机协同。
3. 打开「完整证据链」，说明结论不是黑盒输出，而是可以追溯到指标、日志和工具调用。
4. 进入「流程分析」，用桑基图说明事故在每个阶段的流转与流失，再用漏斗图和延迟图定位优化机会。
5. 进入「AI 评测」，说明离线评测、线上观测、实验对比和 Bad Case 回流如何构成常态化迭代闭环。
6. 在「事故中心」打开任意事故，展示从运营看板下钻到单次处置 Trace 的完整路径。

## 指标口径

| 指标 | 口径 |
| --- | --- |
| 自动化处置率 | 无人工接管并完成恢复判断的事故数 / 已闭环事故数 |
| P0 召回率 | 被模型正确识别为 P0 的事故数 / 实际 P0 事故数 |
| MTTR | 从监控发现到确认恢复的平均分钟数 |
| 商户点击率 | 点击触达消息的商户数 / 成功送达商户数 |
| 单次 AI 成本 | 单次处置中的模型与工具调用成本合计 |
| 阶段成功率 | 阶段成功完成数 / 进入该阶段的事故数 |

## 接入真实后端

当前 Demo 使用 `lib/mock-data.ts` 中的合成数据和 `lib/simulation.ts` 中的确定性模拟器。真实系统可将它们替换为事故事件流、工具调用 Trace、评测结果与人工审批 API；界面组件和指标口径无需改变。
